# Durable local buffers and HA PostgreSQL history

The selected topology is synced bbolt on every RAuth node, forwarding to a central collector backed by a separate event database on the planned Dockerized HA PostgreSQL cluster. SQLite is not used. Extra PostgreSQL servers on workers are not required.

The optional node `events` configuration enables background local buffering, authenticated private delivery and central history. Admin Stats and the live feed use this history; event/telemetry failure never changes authentication readiness. Enabling configuration requires existing guarded directories and an operator-provisioned database. Source support does not establish production HA or imply that host-loss acceptance has passed.

## Local bbolt

An existing private host directory is required. Every path component is opened without following symlinks; files must be regular, private, singly linked and on the directory's device. Runtime mount checks must precede opening it. Missing directories are not created. bbolt holds an exclusive file lock, uses synced commits, and enforces a hard MaxSize on the file. A 24-hour retention limit and conservative accounted-payload budget reserve space for indexes, free pages and copy-on-write commits within the default 2 GiB file cap.

A 1,024-entry queue never waits for disk/network I/O. The background writer assigns stable UUIDs before persistence and retries the same content. Exact-ID acknowledgments delete only delivered records. Queue overflow and permanent batch rejection produce counted gap markers. Evicting a marker carries its represented count and unknown-loss flag forward. Cumulative per-node loss/restart totals let readers recognize rolled-over history without summing it twice; rolling a marker does not increment those totals again. Unclean restart reports possible loss of the unpersisted queue without claiming an exact crash-loss count. Indexed time ranges separate recent live events from catch-up.

## Central PostgreSQL

The collector uses its own credentials and pool, with at least three connections: one actor lock and bounded read/write capacity. It never borrows the authentication pool. Mutations require a writable primary with fsync and full_page_writes enabled and force synchronous_commit=on. HA promotion, synchronous replication and fencing remain deployment responsibilities.

An operator runs Migrate and Provision. The operator owns the tables and needs no superuser/BYPASSRLS privilege. The runtime role is a non-owner, with schema USAGE, SELECT on event_schema_version, SELECT/UPDATE on event_ledgers and SELECT/INSERT/DELETE on request_events and SELECT/INSERT/UPDATE/DELETE on event_traffic_minute/event_node_samples. Provision applies these grants idempotently after migration; runtime credentials remain unable to run DDL. Enabled row security and a role-bound foreign key prevent access to another collector ledger. Runtime credentials have no CREATE, migration or provisioning privilege. Workers need no event-database credentials; mTLS ingestion attributes records to enrolled node identities.

An advisory actor lock and durable owner token fence replaced collectors. Per-ledger cursor allocation commits with content; rollback does not create a false cursor gap. Identical retries are deduplicated and conflicting identity reuse is rejected. An ingestion acknowledgment is returned only after commit. Central retention defaults to seven days and 8 GiB of accounted payload, configurable within bounds. Retention deletes only the necessary oldest records in small transactions and preserves a pruning watermark.

Accounted payload is not physical PostgreSQL disk usage. Tables/indexes, dead tuples, temporary files, WAL, logs and backups need separate capacity protection. Sharing the HA instance also shares WAL/CPU/I/O with authentication. Rate/connection budgets and saturation testing are required; a separate database alone does not provide physical isolation.

All persistence uses explicit host bind mounts, with Pi3 files under /mnt/usb1/rauth and the expected host filesystem UUID checked before creation/start. A missing USB mount must never redirect writes to the system disk. GeoIP lookup remains independent and uses only the master's local database and verified worker copies.

Tests cover privacy, duplicate/lost ACK, conflict/identity rejection, restart cursors, native local filesystem guards and actual process termination, overflow/permanent-error recovery, retention, actor fencing and ordinary PostgreSQL runtime/operator roles. A trigger-injected SQLSTATE 53100 checks rollback/no ACK; actual disk exhaustion, host-loss and resource acceptance remain integration gates. These are RAuth decisions only; no NPM log ingestion or security-audit retention changes.

## Runtime and Stats integration

Run `rauth-event-store -node-config /host/config/node.json -operator-url-file /host/config/event-operator.url -runtime-role rauth_events` offline. The control node JSON must already reference the separate runtime URL file. The operator URL is read only by this command from an existing private file within the same guarded host mount; it is never given to workers or persisted in node runtime state. Use a separate operator staging bind (an existing private host directory with the required guarded node files) so the operator URL is never present in the running application mount. Persist operator credentials only in that protected host staging area. Both URLs require verify-full TLS and explicit read-write leader selection. Create the event database and separate owner/runtime roles through the HA operator first. Back up before upgrade; migration 2 preserves version-1 epochs/cursors and backfills normalized dimensions. Re-run Provision after migration to apply new table grants.

Use 3 ingestion connections (one actor lock plus two operation slots), 2 read-only history connections and 2 read-only Stats connections. These pools are independent of authentication. Per-query deadlines, 2 active Stats builds, 32 cached filter sets and 8 cached history batches bound work and memory. Long traffic windows cache 10s (24h) or 30s (7d). Traffic rollups count only newly committed decisions; pruning subtracts their contributions transactionally. Top lists cover at most the latest 20,000 matching decisions and explicitly label that scope. Optional top-panel timeouts leave aggregate charts available.

Essential snapshots are collected every 5s outside requests. Full registered numeric Go/process/RAuth diagnostics use fixed-label, size-limited chunks every 30s; capture IDs/part counts expose missing parts. No external metrics, map tiles or GeoIP services are queried. Geographical shapes are bundled public-domain Natural Earth data, not an IP location source. Process identities and missing intervals prevent counter-reset spikes; node readiness/spool/delivery observations carry their own times. Active sessions are read once from the control observation, never summed across workers.

Only authenticated assigned EventsWrite peers can submit their own stable node identity. Exact ACK follows the durable commit. Live and catch-up uploads have separate loops and bounded attempts. HTTP 400/409 records are isolated within a bounded retry budget; rejected decisions become durable local loss markers, rejected telemetry leaves explicit sampling coverage gaps, and loss markers themselves are never discarded on rejection. Transport/429/503 failures retain records. Upgrade the collector before workers during protocol changes.

The actual `/rauthmgmt/stats` page, its JSON/history/download/SSE endpoints and `/rauthmgmt/live-feed` require administrator sessions; streams revalidate access every 5s and share 16-global/3-user limits. `/stats` only redirects. `/metrics` keeps its existing network ACL. All request text renders as text, with URL queries/fragments and credentials excluded at collection. Local country assets and responsive charts have table alternatives. Browser acceptance and actual HA/host-loss/resource testing remain deployment gates.
