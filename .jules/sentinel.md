## YYYY-MM-DD - [CRITICAL] Fix DOM XSS in rauthDialog custom UI component
**Vulnerability:** A DOM-based Cross-Site Scripting (XSS) vulnerability existed in `templates/management.html` and `templates/profile.html` due to unsafe string interpolation into `innerHTML` properties within the `rauthDialog` custom dialog system. The variables `title`, `message`, `placeholder`, `defaultValue`, `confirmText`, and `cancelText` were written to the DOM unsanitized.
**Learning:** Even when custom UI components abstract away native dialogs (like `confirm`, `alert`, and `prompt`), user-controlled or dynamically injected parameters are not automatically sanitized. Template literals passed directly into `.innerHTML` represent a classic injection vector if proper escaping is missing.
**Prevention:** Implement and enforce a standard `escapeHtml` utility function across the frontend. Always encode variables before formatting them into HTML structures manually. When using `sed` to automate these frontend replacements via bash scripts, the `&` character in the replacement string must be escaped as `\&` to prevent referencing the matched regex text.
