## 2025-02-28 - Unvalidated Redirect and XSS in Auth/WebAuthn
**Vulnerability:** The application was vulnerable to Open Redirect and Cross-Site Scripting (XSS) via the `rd` (redirect) URL parameter in `internal/handlers/auth.go` and `internal/handlers/webauthn.go`. An attacker could pass a payload like `?rd=javascript:alert(1)` and the application would echo it back in a 302 redirect `Location` header or JSON response for webauthn.
**Learning:** `url.Parse().IsAbs()` returns `true` for URLs with the `javascript:` scheme. Validating only if the hostname is allowed using `IsAllowedHost` is insufficient for absolute URLs because `url.Parse("javascript:alert(1)").Hostname()` returns an empty string (or the domain part of a tricky payload), bypassing the check and causing XSS. Furthermore, some handlers weren't performing *any* validation.
**Prevention:** Always enforce a whitelist of safe URI schemes (e.g., `http` and `https`) for absolute URLs before performing host validation. Extract complex security validations (like redirect sanitization) into centralized helper functions (`ValidateRedirect`) rather than duplicating inline logic across handlers, ensuring uniform protection.
