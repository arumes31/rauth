# Guarded HA host startup and restart supervision

Implements the approved HA deployment/storage guard requirements. Existing state services use restart:no; include the dedicated Tailscale provider and every owned application/observer so daemon startup cannot bypass filesystem validation. This phase remains an isolated fixture and keeps watchdogs off until the separate whole-host maintenance approval and prerequisites pass.

Host-only supervision reuses prepare.py's exact writable UUID and descriptor checks. Before each role restart it checks capacity, private source paths, the expected container identity/authority/mounts and the provider namespace. Startup never creates a new data tree, initializes a cluster, promotes a server or starts retained rollback/legacy authorizers. A failed provider requires stopping its dependent clients before joining its new namespace. Other role failures restart locally with bounded attempts and state-change logging. A missing/wrong filesystem stops only the owned cohort, database first. Docker restart policies remain no; systemd owns boot/recovery.

A host preflight alone has a check/start race if USB disappears and an underlying SD directory exists. Add a small static Go exec guard to each persistent writer's entrypoint. The supervisor attests each actual bind source through held descriptors, writing a root-owned read-only per-role witness on verified /run tmpfs: expected UUID, current host boot ID and each target's physical device, filesystem ID, inode and writable flag. The launcher checks that witness and all required target identities before exec'ing the original image command. Filesystem ID distinguishes disks reusing a device number. Guest processes receive neither Docker control nor a writable witness. The launcher is verified then copied into transient RAM for its read-only bind; all persistent programs/data/config/keys/spools/WAL/backups on Pi3 remain on USB.

The OS unit contains expected mount/UUID and a source-bundle hash. It verifies the mount and reads/pins the program before executing the USB bundle. Bulk programs/configuration remain on the intended host filesystem. It binds lifecycle to Docker and the USB mount, limits restart bursts and does not arm watchdog devices. Remap only node.json operational mount fields and observer output_device after UUID verification and before role start; retain node/cluster IDs, TLS keys, HA URLs and authority.

Tests: malformed/duplicate/aliased witnesses; wrong UUID/boot/device/filesystem/inode/RW scope; symlink/FIFO/ownership; zero child execution on failure; real Linux Python-vs-Go filesystem identity agreement. Fake Docker tests prove zero starts on failed guards, provider ordering, per-role restart limits and unrelated-container isolation. Actual one-host-at-a-time fixture migration and dry-run wrong-UUID refusal precede supervised activation. Preserve all current data and rollback snapshots. Production cutover remains gated on fencing, capacity, backup/restore and full frontend acceptance.
